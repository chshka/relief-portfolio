# 从零复刻石膏浮雕个人网站：单背景到多浮雕长廊

这是一个可复用的制作流程和代码模板，不是把任意网址自动完整复制的工具。它复用本项目实现的视觉机制；素材品质、模型准确度与设备性能仍需要人工验收。

## 0. 先选要做的版本

| 项目 | A：单背景入门版 | B：多浮雕长廊版 |
|---|---|---|
| 适合 | 一张主视觉、内容较少 | 一组系列作品、可扩展展廊 |
| 桌面 | 背景与文字上下滚动 | 浮雕满视口高横排，滚轮左右移动 |
| 手机 | 早期视口背景裁切 | 完整图片等比纵向拼接 |
| 作用方式 | 流场遮罩显现 | 模型从同材质底板隆起 |
| 素材数量 | 1 | 至少2；当前案例为13，不是固定限制 |
| 命令 | --mode single | --mode gallery |

A是保留的早期基线，并非B简单减少图片数量。想要单幅且保留B隆起着色，需要再适配单幅坐标，而不是混用着色器文件。

## 1. 前期准备：给助手什么

建立materials文件夹，每幅放一个子文件夹。准备姓名、昵称、身份、标题、短标语、简介、关键词、真实作品和邮箱；未提供的资料留空。另提供加载页的标志图案。明确电脑/手机滚动方向、完整显示还是裁切、动画范围、静止时能看到多少轮廓，以及是否需要公开上线。

复制资料JSON模板，使用真实内容替换示例；路径相对于JSON。正文是纯文本，不必写HTML。单背景模板是profile.example.json，长廊是profile.gallery.example.json。长廊按panels数组顺序显示，aspect=图片宽/高。新增素材后还要调整内容位置与导航，不能只把文件丢进assets。

工具职责：Codex协调和编辑代码；图像生成制作目标外观/估计深度；Blender处理网格、渲染与导出；Python整理输入和生成项目；浏览器验证运行；Node提供本地HTTP服务。REA只在分析参考网站时提供证据，不是建模器，也不是网页运行组件。

## 2. 拆解参考网站，先确定证据

如用户有参考网址，观察首次进入、加载完成、静止、鼠标经过、移动停止、滚轮、触摸、暂停等状态，记录截图或视频。可检查公开HTML、CSS、JS和资源请求；若使用REA则记录它实际读取了什么。分清“看到了某种效果”“公开代码证实实现方式”和“根据表现推测”，不要把推测写成原站源码事实。

本案例实际成品是原生HTML/CSS/JS与自写WebGL组件，不需要React/Three.js/GSAP作为运行依赖。参考站中出现过的库不等于本站使用过。

## 3. 背景外观：先定材质与构图

选一幅作为样板。保留主体、动作、外框和纵向比例，把旧石纹/裂纹转为中性哑光白石膏，强调圆润大体积与柔和接触阴影。避免强镜面高光、金属银边和烘焙得很黑的阴影。

可用提示词：
> 以我的附件为构图参考，保留人物、饰物与外框，制作正面高浮雕白石膏外观图。主体圆润突出，统一细腻哑光白材质，柔和侧上方光照与接触阴影；不要改变人物姿态，不加文字，不做金属反光。先给外观预览，不声称这是可旋转三维模型。

得到的图仅是外观目标。图片中的阴影不应直接烧进后续高度和最终材质里。

## 4. 从图到高度：关键区别

高度图白处高、黑处低，表示正面表面到基底的距离。普通灰度外观图有阴影和反射，不能直接当准确深度。单图深度估计和AI生成深度都需要检查：脸是否凸出、头发是否分层、手臂与身体前后关系是否合理、剑是否凹陷、外框是否连续。

把主体大体积和微小花纹分开考虑。先控制头、肩、胸、手臂、裙摆等大形体，再叠加细节，适度平滑噪声。单张正面图不能恢复背面、遮挡与倒扣；本路线是面向网站正面观看的2.5D高浮雕。

外观图、线性高度图和模型必须同构图、同比例。修正裁切后应同步更新它们。严禁只凭“看起来很立体”就认为深度准确。

## 5. Blender建立样板

先有经过检查的高度PNG，再运行：
```powershell
& '<Blender路径>' --background --factory-startup --python '<技能目录>/scripts/build_height_relief.py' -- --height './materials/01/height.png' --out './models/01'
```

脚本建立宽2单位的网格，高按图像比例，Z=线性高度×0.26，输出GLB、blend、匹配高度、正面/斜视图与几何统计。160列是起点，不是对所有设备的性能保证。精细人物需要人工修形或专门三维重建，不靠脚手架自动完成。

检查：纯材质、无照片贴图时是否仍立体；头发/脸/手是否正确；正面外框完整，斜面没有锯齿刺；法线与单位正确。当前通用脚本输出开放高度场，不适合直接3D打印；若要封闭实体必须加背板并检查拓扑。案例中的定制plaster-v3做过宏观体积修正和背板，不等同于通用脚本一步输出。

每个模型分别放文件夹，保存原图、高度源、blend、GLB、导出高度和预览。先确认一幅，再按相同标准批量处理，其余模型不要复制首幅人物的局部体积位置。

## 6. 生成网站：先跑通再精调

```powershell
python -X utf8 '<技能目录>/scripts/scaffold.py' --mode single --profile './profile.json' --out './my-single-site'
# 或
python -X utf8 '<技能目录>/scripts/scaffold.py' --mode gallery --profile './profile.gallery.json' --out './my-gallery-site'
cd my-gallery-site
npm run dev
```

浏览器打开 http://127.0.0.1:4173/ 。不需要安装前端运行库或额外打包。项目自带package.json和server.mjs。输出目录必须是新目录，防止覆盖已有成果。模型字段为空时，使用高度图建立备用网格；有GLB时使用实际导出顶点。模型格式严格受限，详情见建模契约。

## 7. 排版：背景层和内容层分开

A：一个背景由整页坐标映射；文字是真实DOM章节。B：每幅在桌面高度等于视口高，宽=高×aspect；总宽为各幅宽之和。背景和文字用同一scrollX，因此没有相对滑动误差。滚轮转换为水平位移，平滑结束，不吸附。手机宽等于屏宽，高=宽/aspect，按scrollY纵排。

B的四块资料初始集中在前六幅以内，后面仅展示浮雕。字块可以跨接缝、上下错落，需看实际人物脸部和复杂纹饰避让。屏幕矮或文字太长时允许字块内部滚动；仍应优先缩减文案而不是塞满。增添作品需同步检查导航、块位置、文字GPU采集节点和手机阅读次序。

不要把文字画死到背景图里：真实DOM负责可读性、复制、链接和无动画降级，GPU文字只是视觉层。

## 8. 动画是几个独立系统合作

1. 输入：收集鼠标/触摸位置与速度，平滑指针；手机监听不阻断原生滚动。
2. 自动路径：虚拟指针沿随机曲线运行，带停顿；用户移动不会重置自动动画。
3. 背景流场：192×192双缓冲保存速度、能量和显现量，逐帧输运、程序卷曲、扩散、衰减。它是流动视觉近似，不是完整流体物理。
4. A显现：白底与受光浮雕按遮罩混合。B隆起：流场驱动顶点高度，同时用有效高度梯度重新计算法线和局部遮蔽；底板和凸起使用同一白石膏材质。
5. 文字：独立手动流场，字形栅格化后做20次方向采样。自动动画不能进入这个流场。选择、暂停或效果失效时恢复DOM。
6. 加载：昵称后方叠图案；初始灰，按资源阶段顺时针填色。字体、首屏深度和模型完成后淡出；失败显示提示但不封锁正文。

当前B的增长从5.5%浅浮雕到100%高度；半径核为exp(-r²/0.0266667)。半径调整k倍应将分母乘k²。参数是实现起点，按屏幕和人物大小验收。关闭动态时显示完整静态浮雕。

## 9. 文件与组件对应

详见components.md的逐文件映射。最常修改的是资料JSON、index.html、style.css、gallery-assets.js；动画主要在relief-flow.js和relief-surface.js，输入与资源在relief-background.js，文字在relief-text.js。

网页不读取Blender场景灯光，而是在WebGL里重算材质；因此Blender渲染和网页不会天然完全一致。当前浏览器上传高度可能只有8位，细节会被量化，模型法线也没有直接作为最终动态法线使用。精细度不足时需要升级几何/高度数据，而不是无限加光照对比。

## 10. 测试后再交付

按verification-and-deploy.md逐项检查：首尾素材、桌面同速、手机触摸、自动文字隔离、暂停、减少动态、异常加载、WebGL恢复和不同屏幕尺寸。至少保存静止、局部隆起、完整静态三种截图，原生看图复核。

性能优化来自单画布、可见绘制、邻近预载、远处释放，以及无手动输入时恢复DOM文字。仍应在真实低端手机测试，不能以开发机无错误代替60fps保证。

## 11. 发布给别人看

127.0.0.1只属于本机。可以把dist部署至Cloudflare Workers静态资源并使用其提供的域名，也可绑定自购域名；无需为这种纯静态站强制租服务器。另一条路线是VPS+Nginx+DNS+HTTPS，需要自行维护。具体步骤及官方链接见verification-and-deploy.md。本技能只在明确要求发布时执行上线，不包含账号/密钥。

## 12. 安装与调用技能

解压发布包，把完整relief-portfolio文件夹放入个人技能目录（通常为用户目录/.codex/skills/），保留SKILL.md和assets/references/scripts的结构；已有同名技能先备份，再替换。新会话中确认技能可见，输入 `$relief-portfolio` 并附资料JSON、素材路径和版本选择。若环境没有技能加载功能，也可让助手读取SKILL.md按流程执行。

单背景提示词和长廊提示词见inputs-and-prompts.md。这份包只包含通用代码和占位模板，不包含当前站主人的资料、人物模型、原站私有资源或生成服务额度。

复刻可重复的是工作流程、布局和交互机制；每个人提供的图片、模型和文案不同，最后的艺术质量需要各自检查。
